# NAVIA — сайт для сбора заявок

Двуязычный (FR/EN) статический сайт. Без базы данных: заявки с формы уходят через Netlify Forms прямо вам на почту.

## Структура

```
navia/
  index.html              ← главная страница (FR)
  mentions-legales.html
  confidentialite.html
  cgv.html
  merci.html              ← страница «спасибо» после отправки анкеты (noindex)
  en/
    index.html             ← главная страница (EN)
    legal-notice.html
    privacy-policy.html
    terms-of-sale.html
    merci.html             ← страница «спасибо» (EN, noindex)
  articles/               ← статьи (FR)
  css/style.css
  js/main.js
  js/analytics.js         ← события для Umami (время, скролл, клики)
  js/consent.js           ← баннер согласия + Google Consent Mode v2
  assets/
    logo.svg
    portfolio/exemple-01.mp4  + exemple-01-photo.jpg   (9:16)
    portfolio/exemple-02.mp4  + exemple-02-photo.jpg   (16:9)
    portfolio/exemple-03.mp4  + exemple-03-photo.jpg   (9:16)
  netlify.toml
```

## Посмотреть локально

Просто открыть `index.html` в браузере — сайт полностью статический, сервер не нужен.

## Деплой на Netlify (бесплатно)

**Вариант А — перетаскиванием (самый простой):**
1. Зайти на [app.netlify.com](https://app.netlify.com), создать аккаунт.
2. На главной странице — "Add new site" → "Deploy manually".
3. Перетащить папку `navia` целиком в окно браузера.
4. Через 10–20 секунд сайт будет доступен по адресу вида `random-name-123.netlify.app`.

**Вариант Б — через Git (удобнее для будущих правок):** залить папку `navia` в репозиторий GitHub, затем в Netlify выбрать "Import from Git" и указать этот репозиторий как корень публикации.

## Обязательно после первого деплоя: включить уведомления формы

Иначе заявки будут просто складироваться в Netlify и вы их не увидите!

1. В панели Netlify → ваш сайт → **Forms**.
2. Откроются формы `commande` (FR) и `order-en` (EN) — они появятся автоматически после первой отправки или после деплоя.
3. Site settings → Forms → **Form notifications** → Add notification → **Email notification** → указать `naviaproduction@gmail.com`.
4. Готово: при каждой заявке будет приходить письмо со всеми ответами анкеты.

WhatsApp-уведомления автоматически не приходят (это было ваше осознанное решение — см. кнопку Click-to-WhatsApp на сайте). Если позже захотите автоматическую пересылку заявок в WhatsApp, это можно сделать через Zapier/Make, подключённый к вебхуку Netlify Forms — отдельная задача, которую можно решить позже.

## Домен navia-production.com

1. Купить домен у любого регистратора (OVH, Gandi, Namecheap — все ок для .com).
2. В Netlify: Site settings → Domain management → Add custom domain → ввести `navia-production.com`.
3. Netlify покажет DNS-записи, которые нужно прописать у регистратора (обычно 1 запись A + 1 CNAME для www). Netlify также бесплатно выпустит HTTPS-сертификат автоматически через несколько минут после настройки DNS.

## Форма и антиспам

Форма использует honeypot-поле (`bot-field`) — скрытое от людей, но видимое ботам, для базовой защиты от спама без капчи.

## Видео примеров: YouTube + фасад

Карточки примеров больше не раздают mp4 с сайта. Устроено так:

| Пример | Формат | YouTube ID |
|---|---|---|
| `exemple-01` — Faire pousser le bien, à toutes les époques | 9:16 | `vQZdULWq4o0` |
| `exemple-02` — Rêver un projet plus grand que soi | 16:9 | `JZKAfjNY8yg` |
| `exemple-03` — Explorer, et faire bouger les choses | 9:16 | `wSNFr__r_ss` |

ID лежат в атрибуте `data-yt` на кнопке `.pf-media` (`index.html` и `en/index.html`)
и в разметке `VideoObject` как `embedUrl` / `url`.

**Плеер грузится только по клику.** На странице стоит статичная картинка-превью,
а `<iframe>` создаётся в [js/main.js](js/main.js) в момент открытия лайтбокса —
и сразу уничтожается при закрытии, поэтому видео останавливается само.

Это не украшение, а необходимость: YouTube ставит cookie и передаёт IP в Google
в момент загрузки iframe. Если вставить плеер прямо в страницу, он сработает **до**
того, как посетитель ответил на баннер согласия, и весь Consent Mode обесценится.
При такой схеме до клика к Google не уходит ни одного запроса, а клик по кнопке
«смотреть» — это и есть осознанное действие. Дополнительно используется домен
`youtube-nocookie.com`.

**Если будете добавлять новый пример:** кнопка получает `data-lightbox="youtube"`
и `data-yt="ID"`, внутрь кладётся `<img>` с превью, а соотношение сторон берётся
из класса `ratio-v` / `ratio-h` на той же кнопке — отдельно его указывать не нужно.

## Страница «спасибо» и конверсии Google Ads

После успешной отправки анкеты форма делает редирект на `/merci` (EN — на `/en/merci`)
вместо инлайн-экрана. Адрес берётся из атрибута `data-success-url` на `<form>`;
если атрибута нет, используется `/merci`.

Обе страницы закрыты от индексации (`<meta name="robots" content="noindex, nofollow">`),
их нет в `sitemap.xml`, и на них не ведёт ни одна ссылка с сайта — так что засчитываться
будут только реальные отправки анкеты.

**Важно:** не добавляйте `/merci` в `Disallow` в `robots.txt`. Если закрыть страницу в
robots.txt, Google не сможет прочитать `noindex` — noindex работает только на тех
страницах, которые роботу разрешено загрузить.

В Google Ads конверсию удобно настроить по правилу «URL содержит `/merci`» — оно
поймает сразу обе страницы, французскую и английскую.

## Тег Google Ads (gtag.js) и Consent Mode v2

Тег `AW-18443303177` стоит ровно один раз в `<head>` каждой HTML-страницы, сразу после
`<meta charset>` и `<meta viewport>`. **Именно в таком порядке — charset обязан попадать
в первые 1024 байта файла, иначе браузер не поймёт кодировку и французские буквы с
диакритикой поедут.** При добавлении новой страницы копируйте весь блок целиком.

Рекламные cookie по умолчанию **запрещены**: перед загрузкой `gtag.js` вызывается
`gtag('consent', 'default', …)`, где `ad_storage`, `ad_user_data` и `ad_personalization`
стоят в `denied`. Дополнительно включены `ads_data_redaction` (Google не получает
данные о навигации, пока согласия нет) и `url_passthrough` (идентификатор клика
передаётся между страницами через URL, а не через cookie).

`analytics_storage` всегда `denied` — Google Analytics на сайте нет, а Umami работает
без cookie и в Consent Mode не участвует.

### Как работает бандо согласия

Файл [js/consent.js](js/consent.js) рисует баннер и отправляет `gtag('consent','update', …)`.

- Две кнопки одного размера: «Tout refuser» / «Tout accepter». Отказаться должно быть
  ровно так же просто, как согласиться — это требование CNIL, не трогайте размеры.
- Выбор пишется в `localStorage` под ключом `navia-consent` на **6 месяцев**, потом
  вопрос задаётся заново.
- Значение из `localStorage` читается прямо в `<head>`, ещё до загрузки `gtag.js`.
  Поэтому у вернувшегося посетителя, который согласился, согласие действует с самого
  первого запроса — «окна» без согласия не возникает.
- Отозвать согласие можно в любой момент ссылкой «Gérer les cookies» внизу каждой
  страницы. Ссылка ставится **слева**, рядом с копирайтом: справа её перекрывала бы
  плавающая кнопка WhatsApp.
- Язык баннера берётся из атрибута `lang` у `<html>`, тексты FR/EN лежат в начале
  `consent.js`.
- События `consent-accept` / `consent-deny` уходят в Umami — видно, какая доля
  посетителей соглашается.

### Что это значит для рекламы

Если посетитель отказался, Google не ставит cookie, и конверсия по нему не будет
засчитана напрямую — она попадёт в **моделируемые конверсии** Google Ads. Это нормально
и ожидаемо: цифры в Ads будут чуть ниже, чем реальное число заявок, зато сайт
соответствует требованиям.

Выбран «расширенный» (advanced) режим Consent Mode: тег грузится сразу и до согласия
шлёт обезличенные пинги без cookie. Это даёт моделирование конверсий. Альтернатива —
«базовый» режим, когда тег вообще не грузится до согласия: строже, но моделирования
не будет совсем. Если захотите переключиться — скажите.

### Чего здесь нет

Это собственный минимальный баннер, а не сертифицированная CMP (Axeptio, Didomi и т.п.).
Для одного рекламного тега этого достаточно. Если позже появятся пиксели Meta, TikTok
и прочие — проще будет поставить готовую CMP, чем расширять этот файл.

## Аналитика посещений (Umami, без cookie)

Счётчик подключён на всех страницах. Он не ставит cookie, не собирает персональных
данных и не требует согласия — поэтому работает независимо от выбора в баннере
(баннер закрывает только рекламные cookie Google Ads). Политика конфиденциальности
обновлена (раздел 9).

Аккаунт: [cloud.umami.is](https://cloud.umami.is), сайт `navia-production.com`,
`data-website-id` уже подставлен во все страницы.

Атрибут `data-domains="navia-production.com"` означает, что статистика пишется
только с боевого домена — локальные открытия и превью-деплои Netlify в отчёты не попадают.

### Какие события отправляются

| Событие | Что означает |
|---|---|
| `time-15s` … `time-300s` | сколько человек реально пробыл на странице (только активная вкладка) |
| `scroll-25` … `scroll-100` | до какой части страницы долистал |
| `view-tarifs`, `view-exemples`, `view-commande`, … | какие секции увидел |
| `cta-order`, `cta-examples` | клики по кнопкам «Créer ma vidéo» / «Voir des exemples» |
| `click-whatsapp`, `click-email` | клики по контактам (в параметре `zone` — шапка, футер, плавающая кнопка) |
| `example-open` | открыл видео или исходное фото в галерее |
| `faq-open` | раскрыл вопрос в FAQ (в параметре — сам вопрос) |
| `form-start`, `form-step-2` … `form-step-5` | воронка формы заказа по шагам |
| `order-sent`, `order-error` | заявка успешно отправлена / ошибка отправки |

Главная воронка в дашборде: просмотры → `view-commande` → `form-start` → `order-sent`.
